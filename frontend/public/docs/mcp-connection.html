Connecting through MCP

Give AI assistants and external tools read-only access to your Promptmaxx data — mentions, rankings, gaps, content, backlinks — through one secure connection.

What you're connecting to

The Promptmaxx MCP server exposes 28 read-only tools over the Model Context Protocol. A connected assistant can answer questions like "how is Zerodha's AI visibility trending?" or "which keywords are within striking distance?" directly from live data.

Safety model: a service API key can read everything in your organisation and can never write — read-only is enforced server-side, per request. It cannot trigger runs, spend model budget, or see any other organisation's data.

Step 1 — Get your API key

1Organization Settings → Get your API key — name the key after its consumer (e.g. claude-desktop, enque-sync) and click Create key.
2Copy the pmxk_… key. It's stored encrypted, so you can copy it again later from the same page — and revoke it there with one click (takes effect immediately).
One key per consumer. The usage box on each key shows exactly what it's being used for — if a key ever surprises you, revoke it.

Step 2 — Connect your client

The MCP server runs on the Promptmaxx server — you don't install anything locally. You connect to one URL with your API key:

URL:            https://app.promptmaxx.co/mcp
Authorization:  Bearer pmxk_your_key_here      # Api-Key pmxk_… also accepted

Both schemes go inside the Authorization header — a bare Api-Key: header of its own is not read. An invalid, revoked or expired key is rejected when you connect (the MCP initialize call returns 401), so a bad key fails fast instead of at the first tool call.

Enque / Claude / your agent (anywhere)
      │  https://app.promptmaxx.co/mcp  + the key
      ▼
Promptmaxx server:  nginx (TLS) ──► MCP service ──► Promptmaxx backend

Claude Code, from any machine:

claude mcp add --transport http promptmaxx https://app.promptmaxx.co/mcp \
  --header "Authorization: Bearer pmxk_your_key_here"

For the server administrator (one-time)

# on the Promptmaxx server, from mcp-server/:
python -m promptmaxx_mcp --http          # serves 127.0.0.1:8010 internally
# run it under a service manager (systemd / NSSM) so it survives restarts,
# and proxy https://app.promptmaxx.co/mcp → 127.0.0.1:8010 in nginx with TLS.
# mcp-server/.env: PROMPTMAXX_BASE_URL=http://localhost:8000  (backend on the same machine)

Each request authenticates with the key it carries, so several consumers with different keys — even different organisations — can share one MCP endpoint safely.

Enque (and other REST consumers): Enque's tool system is manifest-based, not an MCP client — point its tool manifests (or its build-with-AI tool creator) at the Promptmaxx REST API at https://promtmaxxservice.rankmax.io with the same key (Authorization: Bearer pmxk_… or Authorization: Api-Key pmxk_…). Start with the discovery pair: GET /v1/me verifies a key at save time (account, organisation, read-only flag) and GET /v1/workspaces lists the clients the key may reach as {id, name, url} — that id is the domain_id every workspace-scoped endpoint takes. Responses carry X-RateLimit-Limit / -Remaining / -Reset; 429 carries Retry-After (default budget 120 requests/min per key). The key and its permissions are identical either way. Claude Desktop similarly can't attach a raw bearer header to remote connectors — use Claude Code, or a local stdio bridge.
Hosting rules: never expose port 8010 directly to the internet — keep it on localhost or a private network and terminate TLS at a reverse proxy (nginx/caddy) if clients connect from outside; a key on plain HTTP across the internet can be stolen in transit. Run the --http process under a service manager (Task Scheduler / NSSM / systemd) so it survives restarts.

Step 3 — Try it

Ask the connected assistant:

  • "What clients do I have in Promptmaxx?" — calls list_clients
  • "Show Zerodha's latest AI mentions" — resolves the client, calls list_mentions
  • "Which keywords rank today?" — list_seo_keywords

Then open the key's usage box in Settings — you'll see those calls listed.

Troubleshooting

SymptomCause & fix
401 on every callKey missing, mistyped, revoked or expired — copy it again from Settings, or mint a new one. On MCP this now shows up at connect time: initialize itself returns 401.
401 with the key in an Api-Key: headerThe scheme belongs inside Authorization: send Authorization: Api-Key pmxk_… (or Authorization: Bearer pmxk_…).
429 Too Many RequestsPer-key budget exhausted (default 120/min). Honour Retry-After and pace with the X-RateLimit-* headers on the REST API.
403 "error code: 1010" before any JSONCloudflare bot protection rejected the client's User-Agent/IP, not Promptmaxx — send a descriptive User-Agent; if it persists, the Cloudflare rule needs a skip for this hostname (admin).
404 for a domainThe id isn't in your organisation (this is deliberate — existence leaks nothing). Call list_clients for valid ids.
403 on an actionService keys are read-only by design. Writes are impossible with a key.
Connection refusedThe MCP HTTP process isn't running on the server, or you're using the wrong host/port.
Empty rank / report dataNot an auth issue — the instance hasn't run the relevant collector yet (nightly rank crawl, Google connection, first backlink fetch).

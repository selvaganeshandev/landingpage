Confirmed bugs

5 findings · proven on production

Each of these produces a number a user sees that does not match reality. All verified by querying the same records the code reads.

BUG-01

Dashboard “Mentions” card inflates by pile-up

Critical
WhatThe card sums the mentions field across every snapshot date × every platform instead of showing the latest.
EffectThe number grows every time a domain is tracked on a new day. Domains tracked once look correct by coincidence; multi-day domains balloon.
CauseSUM(mentions) over DomainMetricSnapshot with no “latest snapshot” filter.
FixRead the latest snapshot per platform (or the true count), not the sum of all dates.
Kotak — DomainMetricSnapshot: 2 dates × 4 platforms = 8 rows Dashboard SUM(mentions) ........ 25,719 (user sees ~19k in-window) Real answers that named brand .. 876 Bioderma (tracked 1 day) ......... 595 = 595 ✓ matches
BUG-02

Share of Voice dropdown double-counts (×2)

Critical
WhatSums the per-platform rows plus the “Overall” row — but “Overall” already equals the sum of the platforms.
EffectEvery figure is exactly twice the correct value.
CauseThe SoV block reads latest_rows without filtering to the “Overall” scope.
FixUse only the “Overall” row (or sum only the real platforms — never both).
Kotak — own-brand SoV rows (latest day): ChatGPT 4,026 · Claude 929 · Gemini 1,157 · Perplexity 559 → = 6,671 Overall row ................. 6,671 (already the total) Dropdown shows (all summed) . 13,342 Correct value .............. 6,671
BUG-03

Competitor “Mentions” is a stale saved value

High
WhatThe Competitors screen reads Competitor.total_mentions, a saved field that isn’t recomputed when the underlying data refreshes.
EffectShows an old, higher number with no source in the current data.
CauseReprocessing rewrites the raw records but leaves the competitor’s saved total behind.
FixRecompute total_mentions whenever the competitor’s records are reprocessed.
Paisabazaar — stored total_mentions .... 800 Live recompute (133 records) .......... 47 Historical snapshot (2026-08-11) ...... 47 Share of Voice “Overall” .............. 47 ← all agree; only the saved field is wrong
BUG-04

Competitors are measured on only one AI model each

High
WhatCompetitor detection reads only the most recent answer per prompt, so each competitor is measured on a single platform — and which one varies.
EffectCompetitor mentions are undercounted; they miss whatever the other three models said.
Cause.order_by('-tracked_at').first() picks one answer instead of looping over all four platforms (as own-brand analysis does).
FixScan every platform’s answer for competitors, matching the own-brand pipeline.
Own brand (Kotak) .. ChatGPT 354 · Claude 353 · Gemini 393 · Perplexity 399 ✓ all 4 Paisabazaar ........ Perplexity only Hdfcbank ...... ChatGPT only Smartprix .......... Perplexity only Incometax ..... Gemini only
BUG-05

Competitive Strength radar shows a fake “Position = 100”

Medium
WhatCompetitor average position is 0.0 (never calculated), but the formula treats “0” as “ranked #1”.
EffectEvery competitor scores a perfect 100 on the Position axis — they all look like they rank first.
Cause100 − (avg_position × 10) with avg_position = 0 → 100.
FixTreat 0 as “no data” (blank / neutral), not as the best rank.

The single root cause behind almost all of it

Anything read from a stored or aggregated field is stale or double-summed; only the raw answer records are reliable. Every bug here is a variation of one mistake — summing rows that shouldn’t be summed, or reading a saved value that was never refreshed. Fix the read paths (latest snapshot, Overall-only) and the recompute-on-reprocess paths, and every headline number falls back into agreement with the raw truth.
